# شرح هيكلة AutoNegotiater

> الملف هذا يشرح وش بنينا في الأسبوع الثاني: كل قطعة وش تسوي، وكيف تتكلم القطع مع بعض.
> اقراه من فوق لتحت مرة وحدة، وبعدها افتح الملفات المذكورة وشوف الكود.

---

## 1. الفكرة بجملة وحدة

الموقع مقسوم ثلاث طبقات، نفس اللي في تقرير Phase 1 (شكل 4.1):

| الطبقة | وش هي | الأداة عندنا |
|---|---|---|
| **العرض** (Presentation) | الصفحات اللي يشوفها المستخدم | Next.js |
| **التطبيق** (Application) | المنطق: مين يشوف وش، وكيف يمشي التفاوض | FastAPI (ومعه Celery) |
| **البيانات** (Data) | التخزين | PostgreSQL (ومعه Redis) |

القاعدة الأساسية: **الفرونت ما يكلم قاعدة البيانات أبد.** يكلم الباك اند بس، والباك اند هو اللي يقرر وش يرجّع.

## 2. الصورة الكاملة

```
المتصفح
   │  https://autonegotiater.com
   ▼
Cloudflare          ← يخفي السيرفر ويعطي شهادة HTTPS للزوار
   │
   ▼
سيرفر AWS (AlmaLinux)
   │
   ▼
┌─────────────────── Podman (6 حاويات) ───────────────────┐
│                                                          │
│   nginx  ← البوابة الوحيدة المفتوحة (منفذ 80 و 443)       │
│     │                                                    │
│     ├── أي رابط عادي ( / )   →  nextjs   (الصفحات)        │
│     ├── أي رابط يبدأ بـ /api →  fastapi  (الباك اند)      │
│     └── /media               →  صور المنتجات             │
│                                                          │
│   nextjs ──(يطلب البيانات)──►  fastapi                    │
│                                   │                      │
│                                   ├──►  postgresql  (البيانات) │
│                                   └──►  redis       (الطابور)  │
│                                            ▲             │
│                          celery-worker ────┘             │
│                          (مهام الخلفية)                   │
└──────────────────────────────────────────────────────────┘
```

**الحاوية (container)** هي صندوق معزول يشتغل فيه برنامج واحد مع كل اللي يحتاجه. عندنا ست صناديق، كل واحد له شغلة وحدة. والحاويات تكلم بعض بالاسم: fastapi يوصل لقاعدة البيانات على العنوان `postgresql:5432`.

## 3. الـ stack: كل أداة وش تسوي وليش اخترناها

### AlmaLinux
نظام تشغيل السيرفر. هو Linux مجاني ومتوافق مع Red Hat، ومستقر للسيرفرات.

### Podman
يشغّل الحاويات. هو بديل Docker وبنفس الأوامر تقريباً. الفرق إنه يشتغل بمستخدم عادي (`deploy`) بدون صلاحيات root، فلو انخترقت حاوية ما يوصل المخترق لصلاحيات النظام.

**podman-compose** يقرا ملف واحد (`infra/compose.yaml`) فيه تعريف الست حاويات، ويشغّلها كلها بأمر واحد.

### nginx
البوابة. هو الوحيد اللي يستقبل الطلبات من برا، ويوزعها:
- الرابط يبدأ بـ `/api/` ← يرسله لـ fastapi
- أي رابط ثاني ← يرسله لـ nextjs

وهو اللي يمسك شهادة HTTPS على السيرفر. الاسم التقني لشغلته: **reverse proxy**.

### Next.js (الفرونت اند)
إطار عمل مبني على React، ومكتوب بـ TypeScript. يبني صفحات الموقع.

نقطة مهمة: صفحاتنا **server components**. يعني الصفحة تنبني على السيرفر (داخل حاوية nextjs)، والمتصفح يستلم HTML جاهز. عشان كذا طلب البيانات من الباك اند يصير من حاوية لحاوية، مو من متصفح المستخدم.

**Tailwind CSS** هو اللي نستخدمه للتنسيق: نكتب أسماء كلاسات جاهزة مثل `text-lg font-bold` بدل ملفات CSS.

### FastAPI (الباك اند)
إطار عمل Python لبناء الـ API. هو قلب النظام: يستقبل الطلب، يقرا من قاعدة البيانات، ويرجّع JSON.

ليش Python بدل Laravel اللي في تقرير Phase 1؟ لأن محرك التفاوض والـ NLP (FR11) أسهل وأقوى في Python، ومكتبات الذكاء الاصطناعي كلها فيها.

FastAPI يولّد صفحة توثيق تلقائية للـ API: https://autonegotiater.com/api/docs

مع FastAPI نستخدم:
- **SQLAlchemy**: نتعامل مع الجداول ككلاسات Python بدل ما نكتب SQL بيدنا. هذا اسمه **ORM**.
- **Pydantic**: يحدد شكل الـ JSON اللي يطلع من الـ API. وهو اللي يطبق قاعدة الخصوصية (القسم 6).
- **Alembic**: يسجل تغييرات الجداول في ملفات اسمها **migrations**، ويطبقها على قاعدة البيانات بالترتيب.

### PostgreSQL
قاعدة البيانات. فيها الثمان جداول من الـ ERD. اخترناها بدل MySQL لأن فيها نوع **JSONB**، ونحتاجه لشروط العرض في التفاوض متعدد الخصائص (ضمان، توصيل، حالة المنتج) — FR2.

### Redis
مخزن سريع في الذاكرة. الحين له شغلة وحدة: **طابور المهام** بين FastAPI و Celery. وبعدين بنستخدمه للكاش والإشعارات.

### Celery
يشغّل المهام اللي تاخذ وقت **في الخلفية**، بدل ما ينتظر المستخدم.

مثال من الأسابيع الجاية: المشتري يبدأ تفاوض. FastAPI يحط مهمة "نفّذ جولة تفاوض" في Redis ويرد على المستخدم فوراً. Celery يسحب المهمة من Redis وينفذها.

الحين فيه مهمة تجريبية وحدة بس (`ping`)، والمحرك الحقيقي يبدأ في الأسبوع 6.

### Cloudflare
واقف بين الزوار والسيرفر. يدير الدومين (DNS)، ويعطي شهادة HTTPS للزوار، ويخفي عنوان السيرفر.

### GitHub Actions
النشر التلقائي (**CI/CD**). كل ما نرفع كود على `main`، GitHub يدخل السيرفر ويحدّث الموقع بروحه (القسم 8).

## 4. كيف الفرونت يكلم الباك: مثال كامل

وش يصير لما أحد يفتح `https://autonegotiater.com/products`؟

| # | وش يصير | وين في الكود |
|---|---|---|
| 1 | المتصفح يرسل الطلب، ويوصل لـ Cloudflare، وبعدها لـ nginx على السيرفر | — |
| 2 | nginx يشوف إن الرابط ما يبدأ بـ `/api`، فيرسله لحاوية nextjs | `infra/nginx/default.conf` ← `location /` |
| 3 | Next.js يشغّل صفحة المنتجات، والصفحة تنادي `getProducts()` | `frontend/app/products/page.tsx` |
| 4 | `getProducts()` ترسل طلب HTTP إلى `http://fastapi:8000/products`. هذا طلب داخلي من حاوية لحاوية | `frontend/lib/api.ts` |
| 5 | FastAPI يستقبل الطلب في الدالة `list_products` | `backend/app/routers/products.py` |
| 6 | الدالة تطلب المنتجات من PostgreSQL عن طريق SQLAlchemy | نفس الملف، ومعه `backend/app/db.py` |
| 7 | قبل ما يطلع الرد، Pydantic يفلتره بقالب `ProductPublic`. القالب ما فيه `min_acceptable_price`، فالحقل ينحذف | `backend/app/schemas/product.py` |
| 8 | FastAPI يرجّع JSON لـ Next.js | — |
| 9 | Next.js يحط البيانات داخل HTML ويرجّع الصفحة جاهزة | `frontend/app/products/page.tsx` |
| 10 | المتصفح يعرض الصفحة | — |

**الخلاصة:** التواصل بين الفرونت والباك هو **REST API**: طلبات HTTP عادية، والرد بصيغة **JSON**. نفس اللي مكتوب في تقرير Phase 1.

### طريقين للوصول للباك اند
| من وين | العنوان | متى |
|---|---|---|
| من حاوية nextjs (السيرفر) | `http://fastapi:8000/products` | الحين، في صفحة المنتجات |
| من متصفح المستخدم | `https://autonegotiater.com/api/products` | بعدين، للأزرار والنماذج (تسجيل دخول، إرسال عرض) |

في الطريق الثاني nginx يشيل `/api` من أول الرابط قبل ما يرسله لـ fastapi. عشان كذا المسار داخل كود FastAPI هو `/products`، وبرا هو `/api/products`.

عنوان الطريق الأول يجي من المتغير `API_INTERNAL_URL` في ملف `.env`.

## 5. هيكلة المجلدات

```
autonegotiater/
├── frontend/     الفرونت اند
├── backend/      الباك اند
├── infra/        تشغيل الحاويات والسيرفر
├── .github/      النشر التلقائي
├── docs/         التوثيق
├── .env.example  قالب المتغيرات السرية
└── README.md
```

### `backend/` — الباك اند
| الملف | وش فيه |
|---|---|
| `app/main.py` | نقطة البداية. ينشئ تطبيق FastAPI، ويربط الـ routers، وفيه `/health` اللي يتأكد إن قاعدة البيانات شغالة |
| `app/config.py` | يقرا الإعدادات من متغيرات البيئة (`DATABASE_URL`، `REDIS_URL`، ...) |
| `app/db.py` | الاتصال بقاعدة البيانات |
| `app/models/` | **شكل الجداول**. كل كلاس = جدول. `user.py`، `product.py` (المنتجات وقواعد البائع)، `negotiation.py` (الجلسات، العروض، الصفقات، التقييمات، سجل الأحداث) |
| `app/schemas/` | **شكل الـ JSON** اللي يطلع للمستخدم. هنا قاعدة الخصوصية |
| `app/routers/` | **الروابط (endpoints)**. `products.py` فيه `GET /products` و `GET /products/{id}` |
| `app/security.py` | تشفير الباسورد بـ argon2 |
| `app/worker.py` | تعريف Celery ومهامه |
| `alembic/versions/0001_initial_schema.py` | أول migration: ينشئ الثمان جداول |
| `seed.py` | يعبّي البيانات الوهمية: 5 مستخدمين، 25 منتج، 10 قواعد بائع |
| `requirements.txt` | مكتبات Python المطلوبة |
| `Containerfile` | طريقة بناء الحاوية. عند التشغيل ينفذ الـ migrations وبعدها يشغّل السيرفر |

**الفرق بين models و schemas** (سؤال متوقع):
- الـ **model** يوصف الجدول في قاعدة البيانات، بكل أعمدته.
- الـ **schema** يوصف اللي نرسله للمستخدم، وممكن يكون أقل من الجدول.

### `frontend/` — الفرونت اند
| الملف | وش فيه |
|---|---|
| `app/layout.tsx` | القالب المشترك لكل الصفحات (الشريط العلوي) |
| `app/page.tsx` | الصفحة الرئيسية `/` |
| `app/products/page.tsx` | صفحة المنتجات `/products` |

## 6. قاعدة الخصوصية (NFR-03)

المتطلب: المشتري ما يعرف أقل سعر يقبله البائع، والبائع ما يعرف ميزانية المشتري.

كيف طبقناه: جدول `products` فيه عمود `min_acceptable_price`. لكن القالب `ProductPublic` (في `backend/app/schemas/product.py`) **ما فيه هذا الحقل**. و FastAPI يمرر كل رد على القالب قبل ما يطلع، فالحقل ينحذف دايم، حتى لو نسي المبرمج.

وهذا سبب إن الفرونت ما يكلم قاعدة البيانات مباشرة: لو كلمها، ما فيه أحد يفلتر.

تقدر توري الدكتور: افتح https://autonegotiater.com/api/products وبتشوف `base_price` وما بتشوف `min_acceptable_price`.

## 7. قاعدة البيانات

الثمان جداول من الـ ERD في Phase 1:

| الجدول | وش يخزن | مستخدم الحين؟ |
|---|---|---|
| `users` | المستخدمين (مشتري، بائع، مدير) | فيه بيانات وهمية |
| `products` | المنتجات | ✅ يعرضها الموقع |
| `seller_rules` | حدود التفاوض لكل منتج | فيه بيانات وهمية |
| `negotiation_sessions` | جلسات التفاوض | فاضي (أسبوع 6) |
| `offers` | العروض والعروض المضادة | فاضي (أسبوع 6–8) |
| `deals` | الصفقات المنتهية | فاضي (أسبوع 9) |
| `ratings` | التقييمات | فاضي (أسبوع 11) |
| `audit_logs` | سجل كل الأحداث | فاضي (أسبوع 7) |

**كيف تنشأ الجداول؟** ما ننشئها بيدنا. كل ما تشتغل حاوية fastapi تنفذ `alembic upgrade head`، وهذا يطبق أي migration جديد. فلو أضفنا عمود بعدين، نكتب migration جديد وينطبق تلقائياً مع النشر.

**وين تنحفظ البيانات؟** في **volume** اسمه `pgdata`. هو مساحة تخزين برا الحاوية، فالبيانات تبقى حتى لو انحذفت الحاوية وانبنت من جديد.

### الفروقات عن تقرير Phase 1
| في التقرير | اللي سويناه | السبب |
|---|---|---|
| Laravel (PHP) | FastAPI (Python) | Python أنسب لمحرك التفاوض والـ NLP |
| MySQL | PostgreSQL | نوع JSONB لشروط العروض |
| الباسورد SHA-256 | argon2 | SHA-256 سريع جداً، فسهل تخمين الباسوردات فيه. argon2 مصمم للباسوردات |
| شروط العرض نص (`NVARCHAR(MAX)`) | JSONB | نقدر نبحث ونقارن داخل الشروط |

هذي لازم تنكتب في الفصل الخامس.

## 8. كيف الكود يوصل السيرفر (CI/CD)

```
تكتب كود على جهازك
   │  git push
   ▼
GitHub (فرع main)
   │  يشغّل .github/workflows/deploy.yml
   ▼
GitHub Actions يدخل السيرفر بـ SSH كمستخدم deploy
   │
   ├─ 1. يسحب آخر كود
   ├─ 2. يبني الحاويات اللي تغيّر كودها بس
   ├─ 3. يعيد تشغيل nginx
   └─ 4. يفحص /api/health. لو فشل، يطلع الـ run أحمر
```

**البناء حسب المجلد:**
| اللي تغيّر | اللي ينبني |
|---|---|
| `backend/` | fastapi و celery-worker |
| `frontend/` | nextjs |
| `infra/compose.yaml` | الكل |
| `docs/` | ولا شي |

بيانات الدخول للسيرفر محفوظة في **GitHub Secrets**، مو في الكود.

## 9. الأسرار: ملف `.env`

الباسوردات والمفاتيح ما تنكتب في الكود. تنحط في ملف `.env` موجود **على السيرفر بس**، وممنوع يترفع للريبو (مذكور في `.gitignore`).

في الريبو فيه `.env.example`: نفس الملف بدون القيم الحقيقية، عشان أي عضو يعرف وش المتغيرات المطلوبة.

| المتغير | وش هو |
|---|---|
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | بيانات قاعدة البيانات |
| `DATABASE_URL` | عنوان الاتصال اللي يستخدمه FastAPI |
| `REDIS_URL` | عنوان Redis |
| `JWT_SECRET` | مفتاح توقيع تسجيل الدخول (أسبوع 3) |
| `API_INTERNAL_URL` | عنوان FastAPI اللي يستخدمه Next.js |

## 10. أسئلة متوقعة من الدكتور

**ليش قسمتوا المشروع لفرونت وباك منفصلين؟**
عشان كل جزء يتطور لحاله، وعشان المنطق والبيانات الحساسة تبقى في الباك اند. وهذا نفس تصميم الثلاث طبقات في تقرير Phase 1.

**كيف يتواصل الفرونت مع الباك؟**
REST API: طلبات HTTP والرد JSON. Next.js يطلب من FastAPI، و FastAPI يقرا من PostgreSQL.

**ليش غيرتوا من Laravel و MySQL؟**
Python أنسب لمحرك التفاوض والـ NLP. و PostgreSQL فيه JSONB للتفاوض متعدد الخصائص. والتصميم (الثلاث طبقات والـ ERD) ما تغيّر.

**ليش الحاويات (containers)؟**
كل خدمة معزولة ولها بيئتها، ونفس الإعداد يشتغل على أي سيرفر. ولو خدمة طاحت ما تطيّح الباقي.

**ليش Podman مو Docker؟**
يشتغل بدون صلاحيات root، وهو المدمج في AlmaLinux. والأوامر والملفات نفسها تقريباً.

**وش فايدة nginx؟**
مدخل واحد للموقع. يوزع الطلبات بين الفرونت والباك، ويمسك HTTPS. وباقي الحاويات مو مفتوحة للإنترنت.

**وش فايدة Redis و Celery وأنتم ما استخدمتوهم للحين؟**
جهزناهم للتفاوض التلقائي. جولات التفاوض تشتغل في الخلفية عشان النظام يخدم أكثر من جلسة بنفس الوقت (NFR-02) وما ينتظر المستخدم (NFR-01).

**كيف تحمون أقل سعر للبائع؟**
الـ API يمرر كل رد على قالب ما فيه هذا الحقل. والفرونت ما يوصل لقاعدة البيانات أصلاً.

**وين قاعدة البيانات؟ أحد يقدر يوصلها من برا؟**
في حاوية على نفس السيرفر، ومنفذها مو مفتوح للإنترنت. الوصول لها من داخل شبكة الحاويات بس.

**لو أعدتوا تشغيل السيرفر، تضيع البيانات؟**
لا. البيانات في volume برا الحاوية. وفيه سكربت نسخ احتياطي يومي.

**كيف ترفعون التعديلات؟**
`git push` على `main`، و GitHub Actions ينشر تلقائياً ويفحص إن الموقع شغال.

**البيانات الوهمية كيف دخلتوها؟**
سكربت `seed.py` يضيف 5 مستخدمين و 25 منتج في 5 تصنيفات بأسعار بالريال. ولو اشتغل مرتين ما يكرر.

| وش | الرابط أو الأمر |

```bash
podman ps                                   # الحاويات الشغالة
podman logs autoneg-fastapi                 # سجل الباك اند
podman exec -it autoneg-postgresql psql -U autoneg autoneg    # دخول قاعدة البيانات
```

```sql
\dt                                          -- عرض الجداول
SELECT name, base_price, min_acceptable_price FROM products LIMIT 5;
```
الاستعلام الأخير يوريك إن `min_acceptable_price` موجود في قاعدة البيانات، مع إنه ما يطلع في الـ API.
